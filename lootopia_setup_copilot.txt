=======================================================
1. VUE D'ENSEMBLE DU PROJET
=======================================================

Lootopia est une application de chasses au trésor géolocalisées.
Le repo est un monorepo organisé en 3 packages :

  /apps
    /mobile       → App joueurs (React Native)
    /backoffice   → Interface partenaires (React Web)
    /admin        → Console administrateurs (React Web)

  /packages
    /api          → Backend (Node.js + NestJS)
    /shared       → Types TypeScript partagés entre tous les packages

Structure racine du monorepo géré avec npm workspaces (ou Turborepo si tu préfères).

8. DOCKER - INFRASTRUCTURE LOCALE
=======================================================

Créer les fichiers suivants à la racine du repo :

─────────────────────────────────────────
8a. docker-compose.yml  (copier tel quel)
─────────────────────────────────────────

services:
  # ──────────────── PostgreSQL 15 + PostGIS 3.3 ────────────────
  postgres:
    image: postgis/postgis:15-3.3
    container_name: lootopia_postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${DB_NAME:-lootopia}
      POSTGRES_USER: ${DB_USER:-lootopia}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-changeme}
    ports:
      - "5432:5432"
    volumes:
      - lootopia_db_data:/var/lib/postgresql/data
      - ./postgres/init.sql:/docker-entrypoint-initdb.d/01-init.sql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER:-lootopia} -d ${DB_NAME:-lootopia}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s
    networks:
      - lootopia_network

  # ──────────────── pgAdmin 4 ────────────────
  pgadmin:
    image: dpage/pgadmin4:latest
    container_name: lootopia_pgadmin
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      PGADMIN_DEFAULT_EMAIL: ${PGADMIN_EMAIL:-admin@lootopia.local}
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_PASSWORD:-admin}
      PGADMIN_CONFIG_SERVER_MODE: "False"
      PGADMIN_CONFIG_MASTER_PASSWORD_REQUIRED: "False"
    ports:
      - "5050:80"
    volumes:
      - lootopia_pgadmin_data:/var/lib/pgadmin
    networks:
      - lootopia_network

  # ──────────────── MinIO (compatible S3) ────────────────
  minio:
    image: minio/minio:latest
    container_name: lootopia_minio
    restart: unless-stopped
    command: server /data --console-address ":9001"
    ports:
      - "9000:9000"   # API S3
      - "9001:9001"   # Console Web
    volumes:
      - lootopia_minio_data:/data
    environment:
      MINIO_ROOT_USER: ${S3_ACCESS_KEY:-minioadmin}
      MINIO_ROOT_PASSWORD: ${S3_SECRET_KEY:-minioadmin123}
    healthcheck:
      test: ["CMD", "mc", "ready", "local"]
      interval: 15s
      timeout: 10s
      retries: 5
      start_period: 20s
    networks:
      - lootopia_network

  # ──────────────── MinIO init bucket ────────────────
  minio-init:
    image: minio/mc:latest
    container_name: lootopia_minio_init
    depends_on:
      minio:
        condition: service_healthy
    entrypoint: >
      /bin/sh -c "
      mc alias set local http://minio:9000 ${S3_ACCESS_KEY:-minioadmin} ${S3_SECRET_KEY:-minioadmin123} &&
      mc mb --ignore-existing local/${S3_BUCKET:-lootopia} &&
      mc anonymous set download local/${S3_BUCKET:-lootopia}/public &&
      echo 'MinIO bucket initialized.'
      "
    networks:
      - lootopia_network

volumes:
  lootopia_db_data:
    name: lootopia_db_data
  lootopia_pgadmin_data:
    name: lootopia_pgadmin_data
  lootopia_minio_data:
    name: lootopia_minio_data

networks:
  lootopia_network:
    name: lootopia_network
    driver: bridge

─────────────────────────────────────────
8b. postgres/init.sql  (créer ce fichier)
─────────────────────────────────────────

Ce fichier est monté automatiquement au premier démarrage du conteneur postgres.
Il doit activer l'extension PostGIS et créer le schéma initial.

Contenu minimal à mettre dans postgres/init.sql :

  -- Activation de PostGIS
  CREATE EXTENSION IF NOT EXISTS postgis;
  CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

  -- Les tables seront créées par TypeORM (synchronize: true en dev)
  -- Ce fichier sert uniquement à initialiser les extensions nécessaires.

─────────────────────────────────────────
8c. Commandes utiles Docker
─────────────────────────────────────────

  Démarrer l'infrastructure :
    docker compose up -d

  Arrêter :
    docker compose down

  Tout réinitialiser (supprime les volumes) :
    docker compose down -v

  Accès pgAdmin : http://localhost:5050
    email    : admin@lootopia.local
    password : admin

  Accès MinIO console : http://localhost:9001
    user     : minioadmin
    password : minioadmin123

  API S3 MinIO : http://localhost:9000

9. INSTRUCTIONS FINALES POUR COPILOT
=======================================================

- Ne pas implémenter de logique métier dans aucun fichier
- Chaque fichier .ts / .tsx doit exister avec soit :
    a) Un export vide commenté "// TODO: implement"

- Le projet doit pouvoir démarrer sans erreur avec "npm run dev" dans chaque app
- Installer toutes les dépendances listées ci-dessus
- Vérifier que TypeScript compile sans erreur dans chaque package
- Créer le fichier postgres/init.sql avec l'activation des extensions PostGIS et uuid-ossp
- Créer le docker-compose.yml exactement comme indiqué en section 8a
- Créer un README.md à la racine avec :
